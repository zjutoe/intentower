## 1. 这个功能要解决的问题

Intentower 整条链的价值取决于一句话能不能被信任：**「这个模型通过了验收」**。
如果这句话是 Agent 说的，它就没有价值——Agent 会宣告「已测试」「已验证」，而这些宣告可能对应
被跳过的检查、根本没运行的工具，或者一份上一次运行时留下的好结果。

Gate 要解决的具体问题：**把「通过」的定义从人的记忆和 Agent 的口才里拿出来，交给一次可重跑的判定。**

具体要防的失败模式（每一条都真实存在，不是假想）：

1. 旧报告被当成当前结论（模型已经改了，报告还是绿的）。
2. 清单不完整却被当成「全部通过」（0 条义务、重复义务、漏掉的义务）。
3. 求解器没给出结论被含糊地当成通过（`UNKNOWN` / `TIMEOUT` / `UNSUPPORTED` / 工具错误）。
4. Agent 编辑过的 JSON 被当成证据。
5. 判定标准随人漂移：今天说「差不多就算过」，下周说「这次先放行」。

## 2. 意图陈述（Intent statements）

| ID | 意图 |
|---|---|
| **I-01** | 「通过」必须由一次**当前**的判定产生：Gate 自己重新生成证明义务、重新求解，不接受任何先前报告作为输入。 |
| **I-02** | 通过是**合取**，不是印象：当前 POG 构建成功、义务清单完整、至少一条义务、每条义务都是 `SMT_DISCHARGED`、证据与被判定字节绑定。缺任何一项就不是 PASS。 |
| **I-03** | **不确定不等于通过**。除 `SMT_DISCHARGED` 外的任何状态都必须显式呈现，并让判定停在 `INCOMPLETE`。沉默跳过一项检查是最危险的失败模式。 |
| **I-04** | 反例优先于不确定。存在 `NOT_DISCHARGED` 时判定必须是 `FAIL`——用「还有些没查完」掩盖一个反例，等于反向虚报。 |
| **I-05** | 判定必须**说得出为什么**：报告点名涉及哪些义务、清单缺了什么，审查者能据此打开对应文件核对。 |
| **I-06** | 判定的三值（`PASS` / `FAIL` / `INCOMPLETE`）与退出码是稳定契约，脚本与人类依据同一事实行动。 |
| **I-07** | Gate 判定的是**模型的证明义务与证据状态**，不是源代码正确性，也不是人类意图已被正确捕捉（`INT-001` §4 的三条不可混淆结论）。 |
| **I-08** | 判定标准本身属于人类批准范围：Agent 不得为了让 Gate 变绿而放宽 Gate 规范、改判定代码或改基线（`INT-001` C-01 / C-04）。 |

## 3. 人类看到什么，因此要做什么

- 一个三值结论 + 退出码（`0` PASS / `1` FAIL / `2` INCOMPLETE），加上一段点名义务的理由列表。
- 一份机器可读报告：被判定的输入哈希、工具版本、每条义务的状态、清单问题。
- 人类审查动作是：**读结论与理由，抽查一份证据**，而不是重跑全部工具。
- 人类**不接受**：Agent 口头宣告、粘贴的历史 JSON、把 `INCOMPLETE` 描述成「基本通过」。

## 4. 特性级非目标（不改变 `INT-001` §7）

| ID | Gate 明确不做 |
|---|---|
| **NG-01** | 不证明 Rust / Python / C++ 源码正确；Gate 判定的是 Event-B 模型的义务状态与证据状态（`INT-001` NG-04）。 |
| **NG-02** | 不产出内核验证证书，不做独立再验证（计划 §1.3 / §2.7，C-11）。 |
| **NG-03** | 不做密码学签名或防篡改；哈希是流程纪律，不是对抗恶意本地进程的安全边界（`approvals/baseline.json` 同款说明）。 |
| **NG-04** | 不做证明缓存、增量重跑、并行求解（P4 人类裁定：保持可复现优先）。 |
| **NG-05** | 不做 UI / Web / 服务；CLI 就是界面。 |
| **NG-06** | 不自动刷新基线、不自动批准语义变更（P4 §5 D-1、D-2）。 |
| **NG-07** | 不承诺对任意 Event-B 模型都能判定；超出支持子集的义务得到 `UNSUPPORTED`，这是诚实状态而非缺陷（`SPEC-001`）。 |

## 5. 成功判据（可验收，映射 RQ-04）

| ID | 判据 | 由谁验证 |
|---|---|---|
| **S-01** | `0` 条义务、义务缺失、义务重复、清单不可解析，四种情况**都不能 PASS** | `SPEC-003` 边界用例 + Rust 测试（T38）；模型不变量（T36/T37） |
| **S-02** | 证据过期（模型字节或义务产物被改）不能 PASS | 同上 |
| **S-03** | 工具错误 / 超时 / `UNKNOWN` / `UNSUPPORTED` / `STALE` / `MISSING` 一律不能 PASS | 同上 |
| **S-04** | 故意注入的错误实现会被测试抓到（不是只测好路径） | T38 负例 |
| **S-05** | 模型证明与代码测试**分别记录**，任何一处都不写成对方的证据 | T39 审查包 + 各 Gate 记录 |

对应计划 §0.2 **RQ-04**：故意破坏的负例是否都被拒绝。
