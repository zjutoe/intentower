## 1. 这个功能要解决的问题

Intentower 整条链的价值取决于一句话能不能被信任：**「这个模型通过了验收」**。
如果这句话是 Agent 说的，它就没有价值——Agent 会宣告「已测试」「已验证」，而这些宣告可能对应
被跳过的检查、根本没运行的工具，或者一份上一次运行时留下的好结果。

Gate 要解决的具体问题：**把「通过」的定义从人的记忆和 Agent 的口才里拿出来，交给一次可重跑的判定。**

具体要防的失败模式（每一条都真实存在，不是假想）：

1. 旧报告被当成当前结论（模型已经改了，报告还是绿的）。
2. 清单不完整却被当成「全部通过」（0 条义务、重复义务、漏掉的义务）。
3. 求解器没给出结论被含糊地当成通过（`UNKNOWN` / `TIMEOUT` / `UNSUPPORTED` / 工具错误）。
4. Agent 编辑过的 JSON 被当成证据。
5. 判定标准随人漂移：今天说「差不多就算过」，下周说「这次先放行」。

## 2. 意图陈述（Intent statements）

| ID | 意图 |
|---|---|
| **I-01** | 「通过」必须由一次**当前**的判定产生：Gate 自己重新生成证明义务、重新求解，不接受任何先前报告作为输入。 |
| **I-02** | 通过是**合取**，不是印象：人工基线检查通过、选定策略已被该基线钉入、工具版本符合策略、当前 POG 构建成功、义务清单完整、至少一条义务、每条义务都是 `SMT_DISCHARGED`，且基线/策略及验证输入与本轮证据绑定有效。缺任何一项就不是 PASS。 |
| **I-03** | **不确定不等于通过**。`UNKNOWN / TIMEOUT / UNSUPPORTED / TOOL_ERROR / STALE / MISSING` 必须显式呈现，不得汇总成 PASS；在无有效本轮反例时判 `INCOMPLETE`。沉默跳过检查不得产生通过。 |
| **I-04** | 在前置检查通过且本轮证据有效时，反例优先于不确定：存在 `NOT_DISCHARGED` 必须判 `FAIL`，即使还存在未决义务。前置条件失败或本轮证据失效先判 `INCOMPLETE`，不沿用无效上下文中的反例作为本轮结论。 |
| **I-05** | 判定必须**说得出为什么**：报告点名涉及哪些义务、清单缺了什么，审查者能据此打开对应文件核对。 |
| **I-06** | 判定的三值（`PASS` / `FAIL` / `INCOMPLETE`）与退出码是稳定契约，脚本与人类依据同一事实行动。 |
| **I-07** | Gate 判定的是**模型的证明义务与证据状态**，不是源代码正确性，也不是人类意图已被正确捕捉（`INT-001` §4 的三条不可混淆结论）。 |
| **I-08** | 判定标准本身属于人类批准范围：Agent 不得为了让 Gate 变绿而放宽 Gate 规范、改判定代码或改基线（`INT-001` C-01 / C-04）。 |

前置检查失败退出 `2` 且不开始证明；验证后发现基线、策略或本轮输入失效也退出 `2`。只有有效本轮上下文内才应用 I-04 的反例优先规则，精确判定函数见 `SPEC-003` §5。候选 M1 无需预先批准或钉入，仍须保护已有基线。

## 3. 人类看到什么，因此要做什么

- 一个三值结论 + 退出码（`0` PASS / `1` FAIL / `2` INCOMPLETE），加上一段点名义务的理由列表。
- 一份机器可读报告：被判定的输入哈希、工具版本、每条义务的状态、清单问题。
- 预检失败时退出 `2` 并报告实际错误；可写时另存独立失败诊断。历史验证报告保留，但不能作为本轮结论。实际行为与支持边界见 `SPEC-003` §1、§2、§10。
- 人类审查动作是：**读结论与理由，抽查一份证据**，而不是重跑全部工具。
- 人类**不接受**：Agent 口头宣告、粘贴的历史 JSON、把 `INCOMPLETE` 描述成「基本通过」。
