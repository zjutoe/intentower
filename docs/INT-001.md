## 1. 问题：软件工程的核心负担正在从"写"转移到"读"

代码是作者意图的最低层细节。用它作为唯一的审查界面，意味着审查者必须自己从细节里重建意图——这正是软件工程长期存在的认知负担，也是 code review 昂贵、不可扩展的根本原因。

AI Agent 把这个负担反转了：生成代码的成本趋近于零，人类的审查能力却没有同步增长。产出量上升时，人类面对的不再是"我能不能写出这个功能"，而是"我能不能读懂机器写出的这几千行、并判断它是否真的做了我要的事"。

更糟的是，Agent 会自信地宣告"已测试""已验证""功能正常"，而这些宣告可能对应错误的性质、被跳过的检查，或根本没有运行的测试。于是审查者不仅要读更多代码，还要额外花钱去怀疑每一句"成功了"。

**Intentower 的假设**：如果人类只审阅 Intent（含展开过程中经人类裁定并回填的选择），由 Agent 展开和核验 Spec、模型与代码，并由**独立验证器**产生不可口头伪造的证据，那么认知负担可以回到人类可承受的规模。第一阶段就是验证这个假设是否成立；不把技术审查或测试通过当作意图已被正确捕捉的证明。

## 2. 目标用户

| ID | 用户 | 他们要做什么 | 他们不需要做什么 |
|---|---|---|---|
| U-01 | 使用本地 Agent（Pi + Strata）开发关键软件的个人开发者与小团队 | 审阅 Intent、裁定展开时的未决选择；按需阅读证据摘要 | 通读或逐份批准 SPEC / 模型、手写 Event-B、手写证明 |
| U-02 | 需要向他人说明"关键行为为何可信"的开发者（并发边界、金融计算、状态机） | 交付可复现的证据包 | 搭建企业级需求管理系统 |
| U-03 | 不写形式化方法的审查者 / 评审负责人 | 只读顶层承诺与语义摘要，判断 Agent 是否偏离意图 | 逐行读生成代码、检查证明脚本 |

**不是**为形式化方法研究者服务（他们已有 Rodin / Isabelle / ProB），也不是为需要合规工作流的大型组织服务。

## 3. 用户意图优先（Intent-first）

1. 人类拥有并批准 Intent；内容审阅集中于 INT，不另设 SPEC / 模型的人工内容批准。
2. Agent 只能在已批准承诺**之下**工作：展开 SPEC、模型、代码和测试，维护逐项追溯，执行真实检查并按风险接受独立技术复核。
3. 展开中遇到 INT 未决定的重要选择、歧义，或需新增假设、缩小范围、改变可观察承诺时，Agent 暂停依赖工作，展示关联 INT 条款、选项、影响与建议。人类明确裁定后，Agent 忠实回填 INT 并记录裁定来源，再更新下层工件；不得自行选择或重复请求批准同一决定。
4. 交付的"是什么"由 SPEC 描述，"为什么"由 INT 描述；两者都不可从代码反推。
5. INT 已允许范围内的实现细节由 Agent 决定。技术审查通过不等于形式证明、代码测试通过或人类语义批准；历史签署继续保留。已钉工件仍受哈希保护，基线操作批准与内容审阅分开，不自动刷新。

## 4. 不得虚报证明（No false proof claims）

- 任何"已证明 / 已验证"的声明，必须指向由工具生成、含工具版本与输入哈希的证据文件；Agent 的口头宣告无效。
- 只有独立工具（Rossi 生成证明义务 + cvc5 求解）的判定结果才能进入证据。
- 状态枚举固定：`SMT_DISCHARGED | NOT_DISCHARGED | UNKNOWN | TIMEOUT | UNSUPPORTED | TOOL_ERROR | STALE | MISSING`。除 `SMT_DISCHARGED` 外，任何状态都不得被渲染成通过。
- 未运行的检查必须写 `not_run`；计划中的接口不得写成已存在；工具缺失时报告阻塞，不伪造输出。
- 三个不可混淆的结论：`Rossi build successful` ≠ `all POs proved`；`SMT unsat` ≠ `source code proved`；`tests passed` ≠ `human intent captured correctly`。

## 5. 阶段一范围

**包含**：文档化的 Intent / Spec / Refinement / Evidence 四类工件与 ID 关联；至少一组 M0 → M1 Event-B 精化实例；Rossi 解析、检查与证明义务提取；cvc5 对一个明确受限的公式子集自动尝试证明；机器可读结果 + 严格验收 Gate + 人类可读摘要；Pi + Strata 驱动的小任务与有限轮修复；Intentower 自身一个真实功能作为 dogfooding 对象。

**不包含**：见 §7 non-goals。

**判定方式**：见 `Intentower_Phase1_Research_Development_Plan.md` §0.2 的 RQ-01 … RQ-05；P1 是第一个可行性决策点，工具不可用则暂停并换后端，而不是让弱 Agent 重写解析器。

## 6. 目标（Goals）

| ID | 目标 | 成功判据 |
|---|---|---|
| **G-01** | 人类仅审阅 INT（含裁定回填）即可理解 Agent 交付的功能承诺 | 不要求阅读 SPEC / 模型，审查者可正确回答预设行为问题；如实记录 INT 审阅、选择裁定及操作批准耗时（目标 ≤30 分钟）→ RQ-01 |
| **G-02** | 高层规范不变的前提下，Agent 自动完成一次非平凡 M0 → M1 精化 | 生成真实 PO，全部必需义务由自动验证器判定，人工不代写逐项证明 → RQ-02 / RQ-03 |
| **G-03** | 建立不会虚假通过的验收 Gate | 故意破坏的负例（缺 PO、超时、未知、不支持、篡改、过期）全部被拒绝 → RQ-04 |

## 7. 非目标（Non-goals）

| ID | 明确不做 |
|---|---|
| **NG-01** | 不做通用形式化编程语言，不承诺对任意源代码做完全正确性证明 |
| **NG-02** | 不重新实现 Rodin、Rossi、cvc5 或通用定理证明器 |
| **NG-03** | 不承诺支持完整 Event-B 数学语言（并发语义、任意集合 / 关系 / 量词） |
| **NG-04** | 不建立 Event-B 模型与 Rust / Python / C++ 实现之间的形式化对应；初期只做 `implements` / `tests` 可追溯关联 |
| **NG-05** | 不开发 GUI / Web 平台 / 服务端 / 多 Agent 协调器 / 企业级需求管理 / 完整 Contract IR |

## 8. 不可违背的约束（Constraints）

| ID | 约束 | 违反后的后果 |
|---|---|---|
| **C-01** | **意图权威**：人类仅批准 `docs/INT-*.md` 的内容与未决选择；Agent 在已批准 INT 下展开并技术核验 SPEC / 模型 / 测试，不另求人类批准派生内容。需改变承诺或裁定新选择时先提示人类，获裁定后忠实回填 INT；不得先改后报。已钉内容仍须按流程获批后才重钉 | 暂停依赖工作，提交决策单；未获裁定不得采用 |
| **C-02** | **证据唯一**：验证声明必须指向工具生成、含工具版本与输入哈希的证据；口头宣告不构成证据 | 结论视为无效 |
| **C-03** | **不得虚假通过**：Gate 必须从当前模型重新生成 PO 并重新求解，不得信任 Agent 可编辑的旧 JSON；非 `SMT_DISCHARGED` 一律不得产出 PASS | Gate 失败即视为未验证 |
| **C-04** | **独立验证**：判定来自 Agent 未编写的第三方工具；不得通过删测试、放宽规范、忽略错误换取绿灯 | 该次通过作废 |
| **C-05** | **有界自主**：自主修复 ≤2 轮、候选验证 ≤3 次、外部工具必须设超时；超限即停止并升级 | 停止并升级强模型 / 人类 |
| **C-06** | **诚实记录**：未运行的检查写 `not_run`；工具缺失报告阻塞；不伪造命令输出 | 任务状态改为 `blocked` |
